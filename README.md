# AI Generated Articles

Codex CLI をベースに、最新のインターネットニュースを収集し、出典を確認しながらテキストベースの記事を自動生成するツールです。1 回の実行で、1 本の記事を生成します。

このリポジトリでは、ニュース収集、要点整理、記事生成、記事内での根拠提示、自動品質チェックまでを一連のワークフローとして扱います。生成された記事は Markdown で保存し、読者には別システムで Web サイトとして表示される前提です。

## 目的

- 最新ニュースを複数ソースから収集する
- 収集した情報を要約し、重複や矛盾を整理する
- 既存の記事を参照し、近いタイミングで繰り返し実行しても重複記事を避ける
- Codex CLI を使って、記事ごとの構成案と本文を生成する
- 記事ごとに、本文と同じ Markdown 内で出典 URL、取得日時、確認した事実を示す
- Web サイトへの変換に渡しやすい Markdown 形式で記事を出力する

## 想定する使い方

1. `scripts/generate-article.sh` を引数なしで実行する
2. Codex CLI が `PROMPT.md` と `config/` 以下に置かれた任意の設定ファイルをもとに記事化するニュースを選ぶ
3. Codex CLI が Web 検索を使って関連ニュースを収集する
4. 収集結果から信頼できる一次情報や主要メディアの記事を優先して整理する
5. 記事の見出し、要約、本文、参考リンクを生成する
6. 自動品質チェックを通過した記事を Markdown として保存する

## ディレクトリ構成案

```text
.
├── README.md
├── PROMPT.md
├── config/
│   └── ...
├── articles/
│   └── YYYY-MM-DD/
│       ├── topic-slug.md
│       └── another-topic-slug.md
└── scripts/
    └── generate-article.sh
```

## Codex CLI の前提

Codex CLI をインストールし、ログイン済みであることを前提にします。

```console
$ codex login
```

記事生成に必要なシステム上の制約は、ルート直下の 1 ファイルで管理します。

- `PROMPT.md`: 記事生成ワークフロー、保存に必要な最低限の出力形式、情報源の優先順位、採用基準、検証ルール

ユーザーが変更する好み、関心、記事フォーマットは、設定ファイル用のディレクトリに分けて管理します。`config/` 以下には任意の名前でファイルを置けます。

- 例: ユーザーの好み、関心、避けたい内容を記述したファイル
- 例: 記事の文体、構成、見出し、出典表示の好みを記述したファイル

実行時は `PROMPT.md` と `config/` 以下の設定をあわせて参照します。記事フォーマット、読者像、関心、避けたい内容などは、用途に合わせて `config/` 以下の任意のファイルに記述します。`PROMPT.md` は、スクリプトの保存処理や品質確認に必要な最低限の制約を変える場合だけ編集します。

記事生成は、定型作業をまとめたスクリプトを引数なしで実行します。このリポジトリでは、それ以外の生成方法は想定しません。

このスクリプトは次の処理を 1 回のコマンドで行います。

- `articles/YYYY-MM-DD/` ディレクトリの作成
- 生成された記事のトピックに基づく `articles/YYYY-MM-DD/<topic-slug>.md` の作成
- `PROMPT.md` の Codex CLI への標準入力渡し
- Codex CLI の最終メッセージの Markdown ファイル保存

```console
$ scripts/generate-article.sh
```

スクリプトは `PROMPT.md` をそのまま Codex CLI に渡します。`PROMPT.md` の指示に従って Codex CLI が `config/` 以下の設定ファイルと既存の `articles/**/*.md` を参照します。1 回の実行で 1 本の記事を生成します。

出力先は `articles/YYYY-MM-DD/<topic-slug>.md` です。日付ごとにディレクトリを分けますが、1 日 1 本の前提は置きません。近いタイミングで繰り返し実行する前提のため、生成時は既存記事と重複しないトピックや新しい進展を選びます。同名ファイルがすでにある場合は、既存ファイルを上書きせず、末尾に連番を付けます。トピック、出力先、モデルなどはコマンド実行時に指定せず、必要な方針は `PROMPT.md` と `config/` 以下に記述します。

日付ディレクトリは実行環境のタイムゾーンで決まります。必要に応じて、コマンド実行時に `TZ` 環境変数を設定してください。

## 設定例

Web 検索やネットワークアクセスを継続的に使う場合は、`~/.codex/config.toml` で明示します。

```toml
[features]
web_search_request = true

[sandbox_workspace_write]
network_access = true
```

実行環境やセキュリティ要件に応じて、必要最小限の権限で運用してください。

## 記事生成時の方針

- 事実と推測を分けて書く
- 出典のない断定を避ける
- 可能な限り一次情報、公式発表、当事者の発言を優先する
- 複数メディアで裏取りできない情報は本文に採用しない
- 引用は必要最小限にし、本文は独自の要約として作成する
- 日付、固有名詞、数値、リンク、本文中の出典参照は自動チェックの対象にする
- 既存記事と同じニュース、同じ発表、同じ論点の焼き直しを避ける

## 出力記事の形式

生成する記事は Markdown を基本とします。このリポジトリのスコープはテキストベースの記事生成までであり、Markdown から HTML や Web サイトへ変換する処理は含みません。

1 回の実行で生成する記事は 1 本だけです。複数の記事を 1 つの出力にまとめる形式は使いません。

記事の先頭には YAML front matter を置きます。`slug` は `articles/YYYY-MM-DD/<topic-slug>.md` の `<topic-slug>` として使います。`slug` は半角英小文字または半角数字の語をハイフンで区切って書きます。アンダースコア、連続ハイフン、先頭または末尾のハイフンは使えません。スクリプトは `slug` を補正せず、形式が不正な場合は失敗します。

追跡可能性は記事 Markdown の中で確保します。本文中の重要な事実には `[S1]` のような出典 ID を付け、記事内の出典一覧で、各出典が何を確認するために使われたかを示します。見出し構成、本文の並び、出典一覧の名前は `config/` 以下の設定で変更できます。

たとえば初期設定では、次のような構成を使います。

```markdown
---
slug: topic-slug
---

# 記事タイトル

作成日: YYYY-MM-DD
生成日時: YYYY-MM-DD HH:mm TZ
トピック: キーワード

## 要約

- 重要ポイント 1。[S1]
- 重要ポイント 2。[S2]
- 未確定または今後確認すべき点。

## 本文

本文をここに記載します。重要な事実、日付、数値、固有名詞には、対応する出典 ID を付けます。[S1]

## 確認できていること

| 事実 | 根拠 |
| --- | --- |
| 確認した事実 | [S1] |

## 未確認・留意点

- 現時点で確認できない点、出典間で差分がある点、今後更新される可能性がある点。

## 根拠・参考リンク

- [S1] 出典名、公開日、取得日時: YYYY-MM-DD HH:mm TZ、URL、確認した内容
- [S2] 出典名、公開日、取得日時: YYYY-MM-DD HH:mm TZ、URL、確認した内容
```

## 自動品質チェック

記事を Web サイト表示に渡す前に、記事ごとに少なくとも次の項目を自動チェックします。

- リンク切れがない
- 既存記事と重複した記事になっていない
- 日付と時刻が正しい
- 固有名詞の表記が正しい
- 数値や引用が出典と一致している
- 見出しが本文の内容を誇張していない
- 著作権上問題のある長い引用が含まれていない
- 本文中の出典 ID が記事内の出典一覧に存在する
- 読者が記事 Markdown だけで出典と確認内容をたどれる

## 注意事項

このツールはテキストベースの記事作成を完全自動化することを目的とします。記事生成の途中に人間のチェックは挟みません。Markdown から Web サイトへの変換、配信、公開管理はこのリポジトリのスコープ外です。特に速報性の高いニュース、金融、医療、法律、災害、安全保障に関する内容は、自動チェックで公式情報と複数の信頼できる出典を優先して扱います。
