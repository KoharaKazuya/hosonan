# 記事のスタイル、フォーマット、重視するポイント

## 文体

- 日本語で書く
- ですます調を基本にする
- 簡潔で、事実関係を追いやすい文章にする
- 専門用語は必要に応じて短く補足する
- 主観的な評価は、事実と区別して書く

## 記事構成

次の Markdown 形式を基本にします。

```markdown
# 記事タイトル

作成日: YYYY-MM-DD
生成日時: YYYY-MM-DD HH:mm JST
トピック: キーワード

## 要約

- 重要ポイント 1。[S1]
- 重要ポイント 2。[S2]
- 未確定または今後確認すべき点。

## 本文

本文をここに記載します。重要な事実、日付、数値、固有名詞には、対応する出典 ID を付けます。[S1]

## 確認できていること

| 事実 | 根拠 |
| --- | --- |
| 確認した事実 | [S1] |

## 未確認・留意点

- 現時点で確認できない点、出典間で差分がある点、今後更新される可能性がある点。

## 根拠・参考リンク

- [S1] 出典名、公開日、取得日時: YYYY-MM-DD HH:mm JST、URL、確認した内容
- [S2] 出典名、公開日、取得日時: YYYY-MM-DD HH:mm JST、URL、確認した内容
```

## タイトル

- 本文で確認できる事実の範囲内で書く
- 読者が記事の主題をすぐ理解できる具体性を持たせる
- 速報性だけを強調しない

## 要約

- 3 点を目安にする
- 事実、影響、未確定事項の順に整理する
- 本文を読まなくても主要論点が把握できるようにする
- 重要な事実には出典 ID を付ける

## 本文

- 冒頭で、何が起きたのかを簡潔に説明する
- 背景、影響、今後の確認点を順に整理する
- 複数の情報源で内容が異なる場合は、その差分を明記する
- 推測を書く場合は、推測であることを明示する
- 日付、数値、固有名詞、引用、重要な因果関係には出典 ID を付ける

## 確認できていること

- 記事内の主要な事実と根拠の対応を表で示す
- 本文を読み返さなくても、どの出典で何を確認したか分かる粒度にする

## 未確認・留意点

- 未確認情報、出典間の差分、今後更新される可能性がある点を短く書く
- 未確認事項がない場合は「現時点で大きな未確認事項は確認していません」と書く

## 根拠・参考リンク

- 記事中で根拠にした出典のみを載せる
- 公式発表、一次情報、主要メディアの順に並べる
- リンク名は媒体名または文書名が分かる表記にする
- 出典 ID、出典名、公開日、取得日時、URL、確認した内容を含める
- 本文中に出てくる出典 ID がすべて存在するようにする

## 複数記事の扱い

- 1 回の実行で複数の記事を生成する場合も、各記事は単独で読める構成にする
- 記事ごとにタイトル、作成日、生成日時、トピック、要約、本文、確認できていること、未確認・留意点、根拠・参考リンクを含める
- 同じ出来事を扱う記事が複数ある場合は、読者にとって観点の違いが分かるタイトルにする
- 複数の記事を 1 つの出力にまとめる場合は、記事同士を水平線で区切る

## 自動品質チェック

出力前に、記事ごとに次の項目を確認します。

- リンク切れがない
- 日付と時刻が正しい
- 固有名詞の表記が正しい
- 数値や引用が出典と一致している
- 見出しが本文の内容を誇張していない
- 著作権上問題のある長い引用が含まれていない
- 本文中の出典 ID が「根拠・参考リンク」に存在する
- 読者が記事 Markdown だけで出典と確認内容をたどれる
